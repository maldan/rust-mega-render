# Mesh binary format (`MESH`)

Контейнер для `mega_render::Mesh`: один файл — один меш. Все атрибуты **опциональны** и идут **в любом порядке**. Нет чанка — нет канала. Пустой файл после заголовка — валидный пустой меш.

Endian: **little-endian**. Кодировка FourCC и имён: ASCII / UTF-8.

Пока всё пишется «как есть» (`f32` / `u16` / `u32`). Квантование заложено во флагах, но в version 1 **запрещено**.

---

## Файл

```
offset  size  field
0       4     magic    b"MESH"
4       2     version  u16     // 1
6       2     flags    u16
8       …     chunks   до EOF
```

Дальше только чанки. Отдельного `chunk_count` нет: конец файла = конец списка. Обрезанный последний чанк — ошибка.

### `flags`

| бит | имя         | version 1                         |
|-----|-------------|-----------------------------------|
| 0   | `QUANTIZED` | должен быть 0; иначе не читать    |
| 1–15 | reserved   | писать 0; читатель игнорирует     |

Когда квантование появится: тот же layout чанков, другой тип элементов (и, скорее всего, `version += 1` плюс этот бит).

---

## Чанк

Общий заголовок одинаковый для всех типов — поэтому неизвестный FourCC можно пропустить.

```
0    4    id      [u8; 4]   // FourCC, ASCII, верхний регистр, pad пробелами
4    4    size    u32       // байт payload сразу после этого поля
8    size payload
      …   pad     0–3 нуля  // следующий чанк с 4-байтовой границы
```

`pad` **не входит** в `size`. Смещение следующего чанка:

```
aligned = (8 + size + 3) & !3
```

`size == 0` с пустым payload допустим, но такие чанки лучше не писать: нет данных — нет чанка.

Дубликаты:

- `POS`, `NRM`, `TAN`, `IDX` — не больше одного; повтор — ошибка.
- `UV`, `COL`, `JNT`, `WGT` — не больше одного на `(id, slot)`; повтор — ошибка.
- `MRPH` — сколько угодно; порядок в файле = порядок morph target’ов.

Чанки с `count > 0` у вершинных атрибутов (`POS`/`NRM`/`UV`/`TAN`/`COL`/`JNT`/`WGT`/`MRPH`) должны иметь **одинаковый** `count`. Иначе ошибка. `IDX.count` свой (длина индексного буфера).

---

## FourCC

Строковый id, не enum-число. Сравнение — 4 байта как есть (пробелы значимы).

| id     | слот | элемент     | поле `Mesh`              |
|--------|------|-------------|--------------------------|
| `POS ` | нет  | `[f32; 3]`  | rest-позиции             |
| `NRM ` | нет  | `[f32; 3]`  | rest-нормали             |
| `UV  ` | да   | `[f32; 2]`  | `uvs[slot]`              |
| `TAN ` | нет  | `[f32; 4]`  | `tangents` (xyz + sign)  |
| `COL ` | да   | `[f32; 4]`  | `colors[slot]`           |
| `JNT ` | да   | `[u16; 4]`  | `joints[slot]`           |
| `WGT ` | да   | `[f32; 4]`  | `weights[slot]`          |
| `IDX ` | нет  | `u32`       | `indices`                |
| `MRPH` | нет  | см. ниже    | один `MorphTarget`       |

Неизвестный `id`: пропустить `size` байт (+ pad) и продолжить. Так добавляются будущие каналы без bump magic.

Почему не `u8 len + "POSITION"`: заголовок фиксированный, hexdump читаемый, выравнивание простое. Имена длиннее четырёх символов не нужны; семантика в таблице выше.

---

## Payload по типам

После общего `(id, size)` идёт тип-специфичный payload. `size` должен совпасть с длиной этого payload (без pad).

### Без слота: `POS `, `NRM `, `TAN `, `IDX `

```
u32 count
T    items[count]
```

| id     | `T`        | байт на элемент |
|--------|------------|-----------------|
| `POS ` | 3×`f32`    | 12              |
| `NRM ` | 3×`f32`    | 12              |
| `TAN ` | 4×`f32`    | 16              |
| `IDX ` | `u32`      | 4               |

`size = 4 + count * stride`.

`IDX`: triangle list, `count % 3 == 0`. Индексы `<` числа вершин, если вершинные чанки есть; если вершин нет — файл без геометрии с индексами бессмысленен, читатель может отвергнуть.

### Со слотом: `UV  `, `COL `, `JNT `, `WGT `

Слот — колонка как в glTF (`TEXCOORD_0` → `slot = 0`). В файле всегда `u32`, используются младшие биты; сейчас достаточно 0…255. Писать старшие байты нулями.

```
u32 slot
u32 count
T    items[count]
```

| id     | `T`        | байт на элемент |
|--------|------------|-----------------|
| `UV  ` | 2×`f32`    | 8               |
| `COL ` | 4×`f32`    | 16              |
| `JNT ` | 4×`u16`    | 8               |
| `WGT ` | 4×`f32`    | 16              |

`size = 8 + count * stride`.

Дырки в слотах ок: можно записать только `UV` slot 1 без slot 0. В `Mesh.uvs` колонки тогда нужно выровнять пустыми `Vec` либо хранить sparse — решение лоадера; формат этого не запрещает. Рекомендация писателя: плотные слоты с нуля, без дырок.

### `MRPH` — один morph target

```
u16  name_len
u8   name[name_len]     // UTF-8, без NUL
u8   pad_name[0..1]     // до 2-байтовой границы после name_len+name,
                        // фактически: pad так, чтобы следующее поле
                        // (flags) стояло на 4-байтовой границе относительно
                        // начала payload
u32  morph_flags
u32  count
f32  position_deltas[count * 3]
f32  normal_deltas[count * 3]   // только если morph_flags & 1
```

Проще считать выравнивание так: после `name` вставить `0..=3` нулей, чтобы `morph_flags` начинался с `(payload_offset + 0) % 4 == 0` относительно **начала payload**. `name_len` входит в эти байты:

```
name_section_bytes = 2 + name_len
pad = (4 - (name_section_bytes % 4)) % 4
```

| бит `morph_flags` | смысл                                      |
|-------------------|--------------------------------------------|
| 0                 | есть `normal_deltas` (тот же `count`)      |
| 1–31              | reserved, писать 0                         |

Пустое имя допустимо (`name_len = 0`). `count` = числу вершин rest-позы.

`morph_weights` в файл **не входят**: это состояние сцены, не ассета. На load — нули / `0.0`.

---

## Что считается rest-позой

`POS ` / `NRM ` — **rest**, не текущий blend morph’ов.

На load:

1. `positions` ← `POS` (или пусто).
2. `normals` ← `NRM` (или пусто; движок может пересчитать).
3. Если есть хотя бы один `MRPH`: `basis_positions` ← `POS`, `basis_normals` ← `NRM` (если нормалей нет — как в `Mesh::ensure_basis`).
4. `tangents`: чанк `TAN ` как есть; если чанка нет — `compute_tangents` после load.
5. `version` в файл не пишется; после load поставить `1` и при необходимости `mark_changed`.

Не писать blended `positions`. Не писать пустые массивы отдельными чанками.

## Размеры — сводка

```
chunk_bytes = 8 + size + pad4(size)

POS / NRM:  size = 4 + count * 12
TAN:        size = 4 + count * 16
IDX:        size = 4 + count * 4
UV:         size = 8 + count * 8
COL / WGT:  size = 8 + count * 16
JNT:        size = 8 + count * 8
MRPH:       size = aligned_name + 8 + count * 12
                 + (count * 12 if normals)
```

Проверка читателя: вычислить ожидаемый `size` из `count` (и флагов morph) и сверить с полем `size`. Расхождение — ошибка, даже если байт в файле хватает.

---

## Минимальный пример

Один треугольник, только позиции и индексы (без UV).

```
4d 45 53 48     MESH
01 00           version = 1
00 00           flags = 0

50 4f 53 20     POS
28 00 00 00     size = 40
03 00 00 00     count = 3
00 00 00 00  00 00 00 00  00 00 00 00
00 00 80 3f  00 00 00 00  00 00 00 00
00 00 00 00  00 00 80 3f  00 00 00 00

49 44 58 20     IDX
10 00 00 00     size = 16
03 00 00 00     count = 3
00 00 00 00  01 00 00 00  02 00 00 00
```

`POS` payload 40 уже кратен 4 — pad нет. Дальше сразу `IDX`.

Тот же меш с `UV  ` slot 0 можно вставить до или после `POS`/`IDX` — порядок не важен.

## Контракт писателя (version 1)

- Magic `MESH`, `version = 1`, `flags = 0`.
- Не писать чанк, если массив пустой.
- FourCC ровно из таблицы, с пробелами.
- Не ставить `QUANTIZED`.
- Не полагаться на порядок чанков при чтении.
- Не сериализовать `version`, blended-вершины, `morph_weights`.

Читатель отвергает файл, если: неверный magic, `version > 1` (пока нет совместимости вперёд по версии), `QUANTIZED`, обрезанный чанк, несовпадение `size` и `count`, дубликат уникального канала, разные `count` у вершинных атрибутов.
