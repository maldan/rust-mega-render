# Skin binary format (`SKIN`)

Контейнер для rest-скелета и bind-позы `mega_render::Skin`. Один файл — один скин.

`IBM ` — **inverse bind matrix**: переводит вершину из bind-позы меша в пространство кости. Это не иерархия и не имена.

Иерархия берётся с **нод**, на которые смотрит `Skin.joints`. В файл хендлы не пишутся: по хендлу достаём ноду и кладём `name` / `parent` (индекс в этом файле) / rest `local`. Индекс кости = индекс в `IBM ` = индекс в `Mesh.joints` (`JNT`). Веса вершин живут в `MESH`. Поза после анимации — не ассет.

Все чанки **опциональны** и идут **в любом порядке**. Нет чанка — нет данных. Пустой файл после заголовка — валидный пустой скин.

Endian: **little-endian**. FourCC и имена: ASCII / UTF-8.

Пока всё «как есть» (`f32` / `i32` / `u16` / `u32`). Квантование во флагах, в version 1 **запрещено**.

`SkinningMode` (LBS / DQS) в файл не входит: он на `Scene`, не на `Skin`.

---

## Файл

```
offset  size  field
0       4     magic    b"SKIN"
4       2     version  u16     // 1
6       2     flags    u16
8       …     chunks   до EOF
```

Счётчика чанков нет: EOF = конец списка. Обрезанный последний чанк — ошибка.

### `flags`

| бит | имя         | version 1                      |
|-----|-------------|--------------------------------|
| 0   | `QUANTIZED` | должен быть 0; иначе не читать |
| 1–15 | reserved   | писать 0; читатель игнорирует  |

---

## Чанк

Как в `MESH`: неизвестный FourCC можно пропустить.

```
0    4    id      [u8; 4]   // FourCC, верхний регистр, pad пробелами
4    4    size    u32       // байт payload сразу после этого поля
8    size payload
      …   pad     0–3 нуля  // следующий чанк с 4-байтовой границы
```

`pad` **не входит** в `size`:

```
aligned = (8 + size + 3) & !3
```

`size == 0` лучше не писать: нет данных — нет чанка.

Дубликаты: каждый FourCC из таблицы — не больше одного; повтор — ошибка.

`IBM `, `NAME`, `PAR `, `TRS ` с `count > 0` должны иметь **одинаковый** `count`. Иначе ошибка.

Если есть `NAME` / `PAR ` / `TRS ` и нет `IBM ` — ошибка (не к чему биндить).  
`IBM ` без остальных — ок: только матрицы, ноды снаружи.

Неизвестный `id`: пропустить `size` (+ pad) и продолжить.

---

## FourCC

| id     | элемент              | куда в рантайме                          |
|--------|----------------------|------------------------------------------|
| `IBM ` | `Mat4` × count       | `Skin.inverse_bind`                      |
| `NAME` | UTF-8 имена          | `Node.name` суставов                     |
| `PAR ` | `i32` родитель       | `Node.parent` (индекс в этом файле)      |
| `TRS ` | T + Q + S            | rest `Node.local`                        |

---

## Payload

### `IBM ` — inverse bind

```
u32 count
f32 m[count * 16]
```

Каждая матрица — **column-major**, как `glam::Mat4` / glTF: 4 столбца по `xyzw` (16 `f32`).

`size = 4 + count * 64`.

### `NAME`

```
u32 count
для каждого сустава:
  u16 name_len
  u8  name[name_len]     // UTF-8, без NUL
  u8  pad[0..3]
```

Pad после **каждого** имени, чтобы следующее имя (и конец payload) стояли на 4-байтовой границе **относительно начала payload**:

```
name_section_bytes = 2 + name_len
pad = (4 - (name_section_bytes % 4)) % 4
```

Пустое имя допустимо (`name_len = 0` → 2 байта + 2 нуля pad). Нет чанка — имена не заданы, кости адресуются индексом.

`size` обязан совпасть с `4 + Σ (name_section + pad)`.

### `PAR ` — иерархия

```
u32 count
i32 parent[count]
```

`parent[i] == -1` — корень (нет родителя). Иначе индекс сустава в **этом** файле: `0 <= parent[i] < count`, `parent[i] != i`. Цикл в дереве — ошибка.

Лес допустим: несколько корней. У hair-рига все суставы обычно `parent = -1` (ноды без родителя, world-кадр сегмента).

`size = 4 + count * 4`.

### `TRS ` — rest local

Не текущая анимация. Это bind/rest `Transform` для воссоздания нод.

```
u32 count
для каждого:
  f32 t[3]     // translation
  f32 q[4]     // rotation xyzw, как glam::Quat
  f32 s[3]     // scale
```

`size = 4 + count * 40`.

Нет чанка: если ноды всё же создают с `PAR`/`NAME`, `local = Transform::default()` (T=0, Q=identity, S=1).

---

## На load

1. `n ← IBM.count` (или 0, если чанка нет).
2. `Skin.inverse_bind` ← матрицы. `Skin.joints` — пусто, пока нет нод.
3. Если есть `PAR` / `TRS` / `NAME`: создать `n` нод в том же порядке, повесить `parent` по индексу, `local` из `TRS`, имена из `NAME`; записать хендлы в `Skin.joints`.
4. Ноды не обязаны иметь `Node.skin` / mesh / material — это сцена, не этот файл.
5. Индексы в `MESH` `JNT` не меняются.

Не сериализовать: `Handle`, dual-quat (считается из матрицы), `HairChain`, веса вершин, `SkinningMode`.

---

## Размеры

```
chunk_bytes = 8 + size + pad4(size)

IBM:   size = 4 + count * 64
PAR:   size = 4 + count * 4
TRS:   size = 4 + count * 40
NAME:  size = 4 + Σ aligned_name
```

Читатель считает ожидаемый `size` из `count` (и длин имён) и сверяет с полем `size`.

## Пример

Одна кость, без имени и без родителя: только IBM = identity.

```
53 4b 49 4e        SKIN
01 00              version = 1
00 00              flags = 0

49 42 4d 20        IBM
44 00 00 00        size = 68
01 00 00 00        count = 1
00 00 80 3f  00 00 00 00  00 00 00 00  00 00 00 00
00 00 00 00  00 00 80 3f  00 00 00 00  00 00 00 00
00 00 00 00  00 00 00 00  00 00 80 3f  00 00 00 00
00 00 00 00  00 00 00 00  00 00 00 00  00 00 80 3f
```

`TRS ` / `PAR ` можно дописать до или после `IBM `.

## Контракт писателя (version 1)

- Magic `SKIN`, `version = 1`, `flags = 0`.
- Вместе с `IBM ` писать `NAME`, `PAR `, `TRS ` (пустое имя / parent `-1` / default TRS — тоже ок).
- Не писать `Handle`. Rest-поза — `Node.local` на момент сейва (для bind это rest).
- FourCC ровно из таблицы, с пробелами.
- Не ставить `QUANTIZED`.

Читатель отвергает файл, если: неверный magic, `version != 1`, `QUANTIZED`, обрезанный чанк, несовпадение `size` и `count`, дубликат FourCC, разные `count`, `NAME`/`PAR`/`TRS` без `IBM`, битый `parent` (диапазон, self, цикл).
